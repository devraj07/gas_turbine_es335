Research question and motivation

How well can eight contemporaneous operating measurements explain energy yield and emissions, and how stable are those relationships across years? The practical motivation is to assess whether measured operating conditions support useful estimates when direct output measurements are unavailable, and to describe the conflicts between energy production and emissions. The original dataset was introduced for predictive emission monitoring. [1], [2]

This project contributes a comparison of regression models, a descriptive operating-group analysis and a finite-candidate Pareto study. It does not introduce a new learning algorithm or establish a closed-loop controller. Success is judged against a development-mean baseline and linear regression, with separate attention to bias, extreme errors and year-to-year changes.

Data understanding

Before comparing models, the data needs to be checked for completeness, repeated records, unusual values, changes over time and relationships between measurements. A complete table is not sufficient evidence that the observations are representative or independent.

Source files and measurement structure

Each row contains eight operating measurements and three observed outputs. The year is inferred from the filename. The files do not contain a timestamp, equipment identifier, fuel-energy input or maintenance record; elapsed-time behaviour, plant-to-plant generalization and thermal efficiency cannot be established from these columns.

Observations by year

Variables and their roles

The dataset uses native measurement values. No unit conversions are applied. Source-reported units and attribution are given below.

The external dataset is UCI's Gas Turbine CO and NOx Emission Data Set, introduced by Kaya, Tufekci and Uzun. UCI describes hourly average or sum measurements from a turbine in northwestern Turkey, supplied in chronological order for 2011-2015. Dates are omitted. Its recommended benchmark uses 2011-2013 for training/validation and 2014-2015 for testing; this project uses a different comparison protocol, so published benchmark scores are not directly comparable. [1], [2]

Units listed by UCI: AT, TIT, TAT: degrees C; AP, AFDP, GTEP, CDP: mbar; AH: percent; TEY: MWh; CO and NOX: mg/m3. These are source-reported units, not independently calibrated sensor specifications. No conversion is performed. The data is distributed under CC BY 4.0. [1]

Completeness and repeated records

Missing values and infinite values are checked separately. Duplicate measurement rows are counted using all eleven measurements; duplicate input rows use only the eight model inputs. Repeated records are retained in the reported model evaluations. Only the optimization candidate matrix removes repeated input combinations.

No missing values does not mean that every relevant variable is measured. Fuel composition, combustion settings and maintenance history are not available in these files. Their influence cannot be identified or ruled out by this audit.

Statistical outlier flags

A value is flagged when it lies below Q1 - 1.5 IQR or above Q3 + 1.5 IQR in the selected period. This is a screening rule, not a physical acceptance limit.

No values are removed because of this flag. Rare load conditions, sensor behaviour and genuine extremes require different responses; the available measurements do not establish which explanation applies to an individual row.

Histogram construction uses NumPy; displayed bin counts are computed from the complete selected population. [23]

The 1.5-IQR screening fences follow the conventional box-plot definition. [27]

A lack of exact duplicate inputs across periods does not rule out near-duplicate observations or temporal dependence. Feature selection, imputation, scaling and tuning must be fitted within each training partition when evaluating a new pipeline.

Why this choice?

Keeping the eight measured inputs preserves an auditable sensor-to-prediction mapping. The audit finds no missing or nonnumeric measurements, so imputation would add no information. Removing statistical outliers or correlated features was considered as a possible simplification, but the files do not establish measurement faults and no controlled ablation demonstrates a benefit. We retain them and report outlier flags and collinearity instead. Ridge and SVR need comparable feature scales; trees split one variable at a time and use native values. Scaling is fitted inside training pipelines, never on the comparison data. [10], [15]

Feature scales

Standardization uses z = (x - development mean) / development standard deviation. The table uses population standard deviation, matching StandardScaler. These parameters describe a standardized view of the inputs; the final three models still consume native values.

Development median in standardized coordinates

Interpretation

A standardized median far from zero indicates that the mean and median differ relative to the feature's spread. Scaling changes the numerical representation; it does not remove skewness, temporal shift or dependence between inputs.

The prediction page accepts finite numeric inputs and warns when they fall outside individual development ranges. A combination can satisfy every range and still be poorly represented jointly in the historical data. Range validation is not an equipment operating constraint.

Correlated inputs and redundancy

Strongest input correlations

Variance inflation factors

VIF measures how well an input can be explained by the other seven inputs. Large values indicate that linear coefficients can be sensitive to changes in the data. This diagnostic does not establish that a feature should be removed: correlated measurements can still help prediction, especially for nonlinear models. All eight inputs are retained in the final models.

Correlation and VIF are not feature importance estimates. A controlled ablation or permutation study would be needed to measure the effect of removing an input on a specified validation period.

VIF measures variance inflation associated with collinearity. Here it is computed directly by auxiliary least-squares fits, not by a statsmodels dependency. [28]

Development-to-comparison shift

The diagnostics here compare 2011-2014 with 2015. This differs from the original NOX investigation's early-versus-late comparison of 2011-2013 and 2014-2015.

Kolmogorov-Smirnov statistic

Comparison observations outside development ranges

The KS statistic is the largest difference between two empirical cumulative distributions. It identifies distributional differences, not their cause. Target shift and input shift can occur together; these diagnostics alone do not distinguish a changed physical relationship from changes in operating conditions or measurement processes.

Why this choice?

The two-sample Kolmogorov-Smirnov statistic measures the largest separation between empirical cumulative distributions, including changes beyond the mean. It is reported as a descriptive drift diagnostic. Serial dependence makes an independent-sample significance interpretation inappropriate. A small marginal shift also cannot rule out changes in relationships between inputs and targets. [25]

Model evaluation

Evaluation should establish the scale of the errors, where they occur, and whether the comparison period represents the intended use. A single score cannot answer all three questions.

Baseline and model selection

The mean predictor asks whether sensors add information beyond a constant estimate. Ordinary least squares supplies an interpretable additive baseline. Ridge tests coefficient regularization in correlated inputs. Random Forest averages nonlinear trees; Gradient Boosting adds trees sequentially to reduce remaining error. These are established algorithms implemented through scikit-learn. [3], [4], [5], [10], [11], [12]

Why this choice?

A mean baseline makes gains measurable; linear and regularized models test whether added nonlinear complexity is justified. The saved core comparison supports Random Forest for TEY and Gradient Boosting for CO. Linear Regression is retained for NOX in the final synthesis, but its low R-squared and the slightly stronger separate Log Ridge result prevent a claim that it is the best method across all experiments. Model rankings use repeatedly examined 2015 results and therefore remain exploratory. A nested chronological selection exercise and a genuinely independent final dataset would be stronger evidence.

Evaluation design and metric definitions

The main results use 2011-2014 for development and all 7,384 observations from 2015 for comparison. The NOX SVR and transformation experiments use 2014 for validation after fitting on 2011-2013. Repeated inspection of 2015 limits any claim of independent final validation.

MAE

Mean absolute error. The average magnitude of the prediction error, in native target units. Lower is better.

RMSE

Root mean squared error. Larger errors receive greater weight than in MAE. Lower is better.

R-squared

One minus squared error divided by variation around the comparison target mean. One is perfect; negative values are possible. Higher is better.

MAE and RMSE cannot be compared directly across TEY, CO and NOX because their scales differ. R-squared is scale-independent but still depends on the variation present in the comparison dataset. Percentage errors are not used here because near-zero CO observations can make percentage-based metrics unstable.

Why this choice?

Holding out a later year tests transfer across historical periods more directly than a random row split, which can mix nearby operating conditions. Five expanding TimeSeriesSplit folds are used for Ridge tuning and the optimization forest search. These folds preserve row order but do not establish equal elapsed durations because timestamps are absent. The separately reported random 80/20 experiment uses seed 42 and a different evaluation population. [16]

Metric definitions: MAE = mean(|y - prediction|); RMSE = sqrt(mean((y - prediction)^2)); R-squared = 1 - sum((y - prediction)^2) / sum((y - comparison mean)^2). Scores use all comparison rows; plotted points are explicitly subsampled for rendering. [17], [18], [19]

Error distribution and systematic bias

Residual distribution

Residuals against predicted values

Residuals are observed minus predicted. A negative mean residual indicates net overprediction. Mean residual can be small even when individual errors are large, because positive and negative errors cancel. The 90th and 95th percentiles of absolute error describe tail error; they are not prediction intervals.

Random and chronological split results

The baseline random split uses 80% of all-year records for training and 20% for evaluation. The chronological comparison uses 2011-2014 development and 2015 comparison. These protocols differ in both their training population and evaluation population; the difference in scores is not a controlled estimate of leakage or the effect of time alone.

For a new model selection exercise, use repeated chronological validation within development data and reserve an independent later period or external dataset for final evaluation.

Historical operating groups

K-Means was fitted to standardized development inputs. TEY, CO and NOX were not used to create the clusters; their means describe each group afterwards.

Mean value by cluster

Silhouette scores

Cluster 1 has the highest mean TEY and lowest mean CO. Cluster 3 has the lowest mean TEY and highest mean CO. Cluster 2 has the lowest mean NOX. These descriptions are averages of historical records, not safe or optimal operating conditions.

The notebook selects K = 4, with silhouette 0.291. K = 2 scores higher at 0.370, so K = 4 is not the silhouette optimum. The selected DBSCAN configuration finds one non-noise cluster and 0.831% noise; its single-cluster result has no reported silhouette score.

Why this choice?

Standardized K-Means provides compact descriptions of operating groups; DBSCAN tests a density-based alternative with noise labels. K = 2 through 10 were evaluated, with n_init = 10, seed 42, and silhouette sampled on at most 5,000 rows. The notebook fixes K = 4 even though K = 2 has the higher silhouette. Four groups offer a more detailed descriptive partition, but the repository does not document an engineering validation of that choice. DBSCAN searched eps 0.5, 0.7, 0.9, 1.0, 1.2, 1.5, 2.0 and min_samples 5, 10, 15, 20; the retained eps = 1, min_samples = 10 yields only one non-noise group. Neither method identifies optimal or causally distinct regimes. [7], [8], [14], [20]

NOX model investigation

NOX remains the least accurately predicted target in the final synthesis. Linear Regression has MAE 8.181, RMSE 10.215 and R-squared 0.158 on 2015. It overpredicts 74.58% of comparison records. The observed mean NOX increases through 2013, then falls; the data does not identify the cause.

Yearly mean NOX

RBF SVR experiment: 2015 comparison

SVR used standardized inputs and a 12-setting parameter search with 2014 validation. Its 2015 MAE is 9.014, higher than Linear Regression.

Target transformations: 2014 validation

Log Linear Regression, Log Ridge and degree-two Polynomial Ridge were explored. Log Ridge was selected by the transformation experiment and then evaluated on 2015, where MAE is 7.842, RMSE is 9.984 and R-squared is 0.196.

Log Ridge performs slightly better on the saved 2015 comparison than the final Linear Regression selection. The final synthesis and Pareto notebooks nevertheless retain Linear Regression. The repository does not document an additional reason for retaining it; the core-table selection should not be described as the best result across every experiment.

Why this choice?

RBF SVR tests nonlinear smooth relationships; log-target models reduce the influence of high target values; degree-two Polynomial Ridge tests explicit interactions with shrinkage. The log models apply the natural logarithm before fitting and the exponential inverse at prediction, with no documented retransformation-bias correction. The 2014 validation comparison supports Log Ridge within that experiment. Its 2015 R-squared remains only about 0.196, so this is a modest improvement rather than a solved emissions model. Unobserved combustion and fuel conditions are possible explanations, not demonstrated causes. [5], [6], [13]

Model-supported trade-offs

The optimization evaluates 29,342 distinct development input combinations. The outputs shown are predictions from the optimization models, not measured outcomes. A candidate is Pareto-optimal when no other evaluated candidate improves one objective without worsening another: maximize TEY, minimize CO and minimize NOX.

Candidate predictionsAll 56 Pareto pointsSelected representative

Every twelfth candidate is displayed, together with all 56 Pareto points. Pareto membership uses all three objectives; a two-axis projection alone does not establish dominance.

The balanced compromise minimizes the equal-weight Euclidean distance to the ideal point after normalizing the three objectives over the Pareto set. Highest TEY and lowest CO select the same representative here. No emission constraint is added. These are exploratory model-supported candidates, not validated industrial setpoints.

Different TEY forest: notebooks 10-11 tune a 150-tree forest (depth 30, minimum split 10, minimum leaf 2, max_features 1.0). The benchmark and browser predictor use 100 trees (depth 15, minimum split 5, minimum leaf 2). CO and NOX retain the documented Gradient Boosting and Linear Regression configurations. A selected Pareto row can therefore yield a different TEY prediction in the browser explorer.

Why this choice?

Evaluating distinct historical input combinations avoids inventing arbitrary combinations of correlated measurements. Non-dominance retains competing objectives without a single weighted training target. The balanced representative adds an equal-weight, normalized ideal-point preference only after the frontier is found. Different weights, candidate populations or model errors can change the choice; there is no engineering feasibility, uncertainty or emissions-limit constraint. This is finite-set screening, not a continuous or globally optimal search. [9]

Interactive prediction explorer

Open the eight-input predictor

Enter AT, AP, AH, AFDP, GTEP, TIT, TAT and CDP in native dataset units. The page evaluates exported fitted tree structures and linear coefficients as each input changes. It does not retrieve a nearest example or use a preset response. The export is a refit of the documented models on 2011-2014, not a recovered original serialized checkpoint. No scaling or imputation is applied to these three final models. JavaScript tree traversal uses float32 inputs to match scikit-learn.

Saved comparison metrics accompany predictions as context; they are not confidence intervals for a new input. Inputs beyond development ranges are flagged, but an in-range combination is not automatically physically feasible. Eight sliders and synchronized numeric fields update predictions automatically. The three response graphs follow the most recently adjusted input, with the other seven held fixed; these are sampled model responses, not measured effects. Fifty exported Python fixtures test numerical agreement with browser inference; the form tests also check input synchronization, graph values, missing values and reset behavior.

Conclusions and limitations

What the current results support

TEY predictions are close to observed 2015 values, CO predictions have moderate accuracy, and NOX predictions show substantial errors and bias. Clustering describes historical groups. The Pareto analysis compares model-dependent trade-offs within the evaluated candidate set.

TEY is energy yield, not thermal efficiency. No causal effect, real-time control capability, safe operating region or experimental optimum is established.

Before operational use

  • Verify units, sensor definitions, equipment identity and timestamps.
  • Validate on an independent later period and, where relevant, another turbine.
  • Define acceptable errors and asymmetric costs for each target with domain specialists.
  • Evaluate uncertainty calibration, drift monitoring and missing-sensor handling.
  • Test failure cases, enforce engineering constraints and validate any proposed operating change experimentally.

These are future validation requirements, not capabilities demonstrated by the current project. The current evidence does not establish readiness for operational deployment.
